## Hook

## How it works

The AWS-style model creates a delete marker for an unqualified delete; deleting that marker may reveal an older version. The GCP-style model removes the live generation without creating a marker, and archived generations do not automatically become live. Conditional model tokens reject stale writes; archived expiry uses time since becoming noncurrent.

### AWS and GCP comparison

AWS: S3 version / delete-marker concepts. Google Cloud: Cloud Storage object generations. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## When to use

Use this scenario when reviewing S3 version / delete-marker concepts or Cloud Storage object generations: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

Tokens are teaching SHA-256 values, not real ETags or native generation-match conditions. Lifecycle policy, retention locks, replication and permissions need provider-specific design.
