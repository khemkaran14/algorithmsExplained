## Hook

## How it works

Canonical IPv4 routes use longest-prefix matching and declared tie priority. Internet-gateway traffic requires public mapping; NAT permits a mapped reply after outbound initiation. Local/peering paths and blackholes are separate route choices. Firewall policy and return-flow state are independent gates.

### AWS and GCP comparison

AWS: VPC routes / internet gateway / NAT concepts. Google Cloud: VPC subnet routes / Cloud NAT concepts. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## When to use

Use this scenario when reviewing VPC routes / internet gateway / NAT concepts or VPC subnet routes / Cloud NAT concepts: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

This is a bounded five-tuple teaching model, not TCP, a complete NAT implementation or all AWS/GCP route precedence. NAT is not an inbound authorization mechanism.
