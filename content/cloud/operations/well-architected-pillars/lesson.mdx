# Well Architected Pillars

## Hook

A low estimated bill cannot cancel a critical identity-policy problem.

## Watch

Load the average scenario and step through the initial state before playing. Read the variables and final result, then switch to the worst scenario. Pause before a decision and predict which explicit condition determines the next action.

## How it works

A declared review checks healthy and one-zone-loss processing capacity, instance budget, tested restore evidence, database exposure, identity scope, alert ownership and retention review. Each failed constraint stays independently actionable. Round-robin zone placement determines the largest failed-zone loss; no aggregate quality score hides security or recovery gaps.

### AWS and GCP comparison

AWS: AWS Well-Architected review concepts. Google Cloud: Google Cloud Well-Architected review concepts. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Try it

Add replicas to survive a zone loss, then inspect the budget consequence. Leave public DB exposure enabled and explain why a passing cost check does not resolve security. Record missing restore and alert evidence as actions. In Try mode, choose the next modeled decision and use the hint to inspect its preconditions. Explain a changed result using the actual input rather than the provider logo.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## Code

References isolate capacity/budget evidence. Explicit security, operational and retention checklists remain in the player. All four languages show local reference logic rather than provider SDK calls. Validate inputs and account for the unmodeled production concerns before adapting a reference.

## When to use

Use this scenario when reviewing AWS Well-Architected review concepts or Google Cloud Well-Architected review concepts: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

This is not a provider assessment, certification, SLA or total-cost calculation. Framework pillars differ by provider, and actual evidence, threat models, sustainability measurements and business requirements need review.

## Quiz

Answer the mechanism question, distinguish the exercise from a real cloud operation, and justify a controlled failure experiment. Re-run the scenario if your prediction disagrees with the traced state.
