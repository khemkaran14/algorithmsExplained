## Hook

A canary with no useful sample cannot justify promotion.

## Watch

Load the average scenario and step through the initial state before playing. Read the variables and final result, then switch to the worst scenario. Pause before a decision and predict which explicit condition determines the next action.

## How it works

Tests, policy and signature gates reject an ineligible immutable candidate before traffic. Seeded observations at 10%, 25% and 50% candidate traffic measure both absolute error and regression versus contemporaneous baseline. Insufficient candidate samples hold; exceeded guardrails roll back; all successful stages promote.

### AWS and GCP comparison

AWS: CodePipeline / CodeBuild / deployment concepts. Google Cloud: Cloud Build / Cloud Deploy concepts. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Try it

Set candidate errors to 100% and inspect rollback. Use one request per stage to force hold. Then set both error assumptions to zero with enough observations and verify promotion. In Try mode, choose the next modeled decision and use the hint to inspect its preconditions. Explain a changed result using the actual input rather than the provider logo.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## Code

References isolate the gate and observed-stage decision. The player generates deterministic observations and applies traffic transitions. All four languages show local reference logic rather than provider SDK calls. Validate inputs and account for the unmodeled production concerns before adapting a reference.

## When to use

Use this scenario when reviewing CodePipeline / CodeBuild / deployment concepts or Cloud Build / Cloud Deploy concepts: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

Synthetic requests are not statistical significance, actual build results or a real deployment. Supply-chain trust, approval policy, migration compatibility and production monitoring remain operational requirements.

## Quiz

Answer the mechanism question, distinguish the exercise from a real cloud operation, and justify a controlled failure experiment. Re-run the scenario if your prediction disagrees with the traced state.
