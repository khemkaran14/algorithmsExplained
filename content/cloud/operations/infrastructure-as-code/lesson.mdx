# Infrastructure As Code

## Hook

A state file that says two instances exist does not prove reality matches it.

## Watch

Load the average scenario and step through the initial state before playing. Read the variables and final result, then switch to the worst scenario. Pause before a decision and predict which explicit condition determines the next action.

## How it works

A desired-state diff compares refreshed actual resources or stale recorded state. Region is immutable and produces replacement; size produces update. preventDestroy blocks the whole destructive plan before mutation. Apply can fail between resource operations; prior successful actions remain, and a refreshed follow-up plan resumes.

### AWS and GCP comparison

AWS: CloudFormation / Terraform-on-AWS concepts. Google Cloud: Infrastructure Manager / Terraform-on-GCP concepts. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Try it

Create drift between recorded and actual size, then compare refresh enabled and disabled. Inject failure before action one and inspect the remaining plan. Change region with preventDestroy enabled. In Try mode, choose the next modeled decision and use the hint to inspect its preconditions. Explain a changed result using the actual input rather than the provider logo.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## Code

References implement pure planning and destructive-plan rejection. The player also applies bounded atomic resource operations and retains partial success. All four languages show local reference logic rather than provider SDK calls. Validate inputs and account for the unmodeled production concerns before adapting a reference.

## When to use

Use this scenario when reviewing CloudFormation / Terraform-on-AWS concepts or Infrastructure Manager / Terraform-on-GCP concepts: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

No real resources, HCL parser, cloud credentials or deployment run. Dependency graphs, state locking, imports, provider retries and non-atomic replacement need further production design.

## Quiz

Answer the mechanism question, distinguish the exercise from a real cloud operation, and justify a controlled failure experiment. Re-run the scenario if your prediction disagrees with the traced state.
