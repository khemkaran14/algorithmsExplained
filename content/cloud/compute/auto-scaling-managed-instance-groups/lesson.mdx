# Auto Scaling Managed Instance Groups

## Hook

Scaling after a spike cannot serve the requests that arrived before a new instance was ready.

## Watch

Load the average scenario and step through the initial state before playing. Read the variables and final result, then switch to the worst scenario. Pause before a decision and predict which explicit condition determines the next action.

## How it works

A bounded controller computes desired instances from lagged offered demand and target utilization. Startup delay separates allocated from serving capacity; cooldown and sustained low demand constrain oscillation. FIFO capacity completes old work before new arrivals, and queues have explicit limits.

### AWS and GCP comparison

AWS: EC2 Auto Scaling. Google Cloud: Compute Engine Managed Instance Groups. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## When to use

Use this scenario when reviewing EC2 Auto Scaling or Compute Engine Managed Instance Groups: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

This demand-derived controller is not an implementation of either provider’s autoscaler. Product metrics, health replacement, warm pools and stabilization behavior differ.
