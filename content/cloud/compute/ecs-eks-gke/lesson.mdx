# Ecs Eks Gke

## Hook

Managed orchestration changes operational duties, but rollout capacity is still finite.

## Watch

Load the average scenario and step through the initial state before playing. Read the variables and final result, then switch to the worst scenario. Pause before a decision and predict which explicit condition determines the next action.

## How it works

The same declared replica controller separates desired state, placement capacity and service readiness. Surge makes temporary extra capacity available; maxUnavailable limits deliberate removal of old ready endpoints. A failed node is an involuntary failure and can exceed that rollout budget.

### AWS and GCP comparison

AWS: ECS task/service and EKS Kubernetes concepts. Google Cloud: GKE Kubernetes concepts. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Try it

Reduce healthy node slots during a rollout. Decide whether to add node capacity, accept an unavailable budget or wait; do not assume surge overrides physical resources. In Try mode, choose the next modeled decision and use the hint to inspect its preconditions. Explain a changed result using the actual input rather than the provider logo.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## Code

References isolate the rollout decision. Scheduling resources, node faults and readiness histories surround that core in the player. All four languages show local reference logic rather than provider SDK calls. Validate inputs and account for the unmodeled production concerns before adapting a reference.

## When to use

Use this scenario when reviewing ECS task/service and EKS Kubernetes concepts or GKE Kubernetes concepts: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

ECS tasks/services and EKS/GKE pods/controllers are not interchangeable APIs. This shared conceptual model does not imply equal features, node management or prices.

## Quiz

Answer the mechanism question, distinguish the exercise from a real cloud operation, and justify a controlled failure experiment. Re-run the scenario if your prediction disagrees with the traced state.
