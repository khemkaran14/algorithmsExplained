# Containers Kubernetes Basics

## Hook

A running container is not automatically a ready service endpoint.

## Watch

## How it works

A controller reconciles target-version replicas within a surge cap. A scheduler selects healthy nodes with available slots. Only ready pods receive service traffic; an old ready endpoint is deleted only within the declared unavailable budget. Unready old pods can be removed without losing another ready endpoint.

### AWS and GCP comparison

AWS: Container image / ECS and EKS concepts. Google Cloud: Container image / GKE concepts. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## Code

## When to use

Use this scenario when reviewing Container image / ECS and EKS concepts or Container image / GKE concepts: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

This bounded scheduler is not Kubernetes, ECS or kubelet. Readiness probes, networking, image provenance, volumes and disruption budgets are additional systems.
