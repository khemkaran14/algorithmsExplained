# Regions Availability Zones

## Hook

Three replicas in one building are still one failure domain.

## Watch

Load the average scenario and step through the initial state before playing. Read the variables and final result, then switch to the worst scenario. Pause before a decision and predict which explicit condition determines the next action.

## How it works

Primary replicas acknowledge only with a fixed majority. Round-robin placement across zones survives a zone loss when enough votes remain. A whole-region outage is a separate fault; adding zones inside that region cannot survive it.

### AWS and GCP comparison

AWS: AWS Regions / Availability Zones. Google Cloud: Google Cloud regions / zones. Select the provider mapping before loading input. Product names identify concepts; they do not create resources, imply identical APIs or promise equivalent service guarantees.

## Complexity

The player displays the model's operation metric and declared bounds. Compare best, average and worst presets before changing only one parameter. Simulation operation counts are different from provider quotas, cloud bills, throughput benchmarks and wall-clock service latency.

## Code

The four references isolate fixed-majority admission and failover timing; the player also tracks completed asynchronous snapshots and lost acknowledged record IDs. All four languages show local reference logic rather than provider SDK calls. Validate inputs and account for the unmodeled production concerns before adapting a reference.

## When to use

Use this scenario when reviewing AWS Regions / Availability Zones or Google Cloud regions / zones: identify the workload assumption, failure boundary and evidence needed for the selected design. Record one alternative and the constraint it changes.

## Interview pitfalls

The exercise does not claim a cloud SLA or emulate a provider control plane. Correlated power, network and account failures need a broader threat model.

## Quiz

Answer the mechanism question, distinguish the exercise from a real cloud operation, and justify a controlled failure experiment. Re-run the scenario if your prediction disagrees with the traced state.
