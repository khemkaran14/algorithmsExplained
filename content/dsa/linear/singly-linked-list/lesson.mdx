## How it works

1. Keep head and tail node identities.
2. Append by changing the old tail’s next link.
3. Search by following next links.
4. Delete the first matching node by bypassing it and repairing head or tail.

## Complexity

Appending with a tail pointer is O(1). Searching by key is O(n); deleting after a known predecessor is O(1). Visualization snapshots are separate from the data structure’s logical operation costs.

## When to use

Use linked lists when stable node identities and local link updates matter more than random indexing and memory locality.

## Interview pitfalls

Deleting the head or final node requires updating end pointers. Equal values still belong to distinct nodes.
