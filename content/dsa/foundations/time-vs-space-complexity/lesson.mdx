## How it works

1. Try a constant-space scan of every pair.
2. Try a set that remembers earlier keys.
3. Compare the work counters and stored-key count.

## Try it

Predict each decision before advancing. The player checks against the real model and explains why an alternative move fails.

## Complexity

The pair method is quadratic without an early duplicate. Hash-set lookup is expected constant time per key but uses linear extra memory. The chart labels identify actual counters or explicitly modeled recurrence work; display snapshots are not charged to the underlying algorithm.

## Code

Switch among JavaScript, Python, Java and C++. The active conceptual stage and live variables connect the code to the trace.

## When to use

Use this trade-off when remembering previous work avoids repeated scans.

## Interview pitfalls

Expected hash-table performance is not a universal worst-case guarantee. Extra memory must be counted separately from time.
