# Bipartite Check

## Hook

Seat each connected acquaintance on the opposite side from their neighbor.

## Watch

Every edge must cross the two sides. Edit the graph JSON to add a cycle, isolate a vertex or change an edge weight. Nodes are numbered from zero.

## How it works

1. Color a new component seed.
2. Give every new neighbor the opposite color.
3. Reject an edge between equal colors.

## Try it

Predict the next frontier decision or edge operation before revealing it. Compare a connected graph with the same graph after removing an important edge.

## Complexity

O(V+E). Two-color BFS visits every component. An equal-color edge closes an odd-cycle obstruction, while successful parity assignments satisfy every edge. The counters count teaching operations; animation duration is not a CPU benchmark.

## Code

The four references show the core operation. Adjacency-list inputs use zero-based vertex indices. Weighted references use (neighbor,weight) pairs or explicit edge triples. Validate the graph assumptions before calling standalone code.

## When to use

Use for two-way partition constraints and as a matching prerequisite.

## Interview pitfalls

An odd cycle or a self-loop prevents a two-coloring.
