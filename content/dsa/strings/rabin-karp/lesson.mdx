# Rabin Karp

## Hook

A quick fingerprint rejects most windows before an exact character comparison.

## Watch

Filter by a rolling hash, then verify. Use a repeated-character input and compare the resulting counters with a less repetitive example.

## How it works

1. Hash the pattern and first window.
2. Compare equal-length window fingerprints.
3. Verify equal hashes character by character.
4. Remove the outgoing character and add the incoming one.

## Try it

Predict a character comparison, run extension, palindrome expansion or merge frequency. Step back and explain which stored state avoided repeated work.

## Complexity

O(n+m) expected, O(nm) worst, O(1) auxiliary space. The player explains the relevant invariant and counts actual comparisons, reads and writes. Output storage is reported separately when it grows with the result.

## Code

The four references assume the lesson’s printable ASCII input contract. The foundation Strings lesson separately explains Unicode code points and UTF-16 units. Pattern inputs must be nonempty; text may be empty for matching. Huffman and palindrome inputs must be nonempty.

## When to use

Use for fingerprint-based candidate filtering and extensions to multiple-pattern matching.

## Interview pitfalls

Hash collisions are possible. This model always verifies candidates and uses safe integer arithmetic under its bounded inputs.
