# Transactions

## Hook

A transaction must publish its changes together or publish none of them.

## How it works

BEGIN creates a transaction identity, reads observe visible committed versions plus the transaction’s own writes, and writes accumulate privately. COMMIT publishes the complete write set atomically after conflict checks. ROLLBACK discards the private set. The model ends transaction IDs rather than silently reusing them.

## Try it

## When to use

Grouping related data changes into a clear commit/rollback boundary.

## Interview pitfalls

This model uses deferred absolute writes, not a full SQL executor or SQL UPDATE arithmetic. Production transactions also need physical locks, persistence and recovery. A business invariant across rows is not enforced merely by placing operations between BEGIN and COMMIT.
